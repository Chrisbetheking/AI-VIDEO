TokenFence Studio｜Local-first AI Safety and Multi-model Orchestration Workspace

Open-source project: a pre-LLM safety and routing layer before prompts reach cloud or local models.

TokenFence Studio sits between user input and model calls. Before a prompt is sent, it performs local risk scanning, sensitive-content redaction, context compression suggestions, and model routing, then visualizes the final prompt, risk status, and routing result.

StackNext.js 14, React, TypeScript, Tailwind CSS, Zod, Commander, tsx, MCP SDK
Prompt safetyScans API keys, emails, phone numbers, database URLs, access tokens, secret assignments, and Chinese ID patterns locally.
Model orchestrationProvider Registry, multi-model comparison, file-level routing, risk status, token usage, and latency display.
Tooling entry pointsWeb Studio, CLI command, local archive, provider settings, Agent Context Pack, and MCP Server prototype.

Front-end / product work

  • Built Chat Workspace, Provider Management, Prompt Guard, Model Matrix, and Local Archive views so the core capabilities are available as an interactive product interface.
  • Turned risk level, redaction result, policy profile, model choice, file routing, and run archive into readable UI.
  • Organized Strict / Balanced / Fast / Developer policies to make the safety-speed tradeoff clear.

Engineering / AI tooling

  • Separated scanner, redactor, risk engine, compressor, intent engine, and provider adapters for future extension.
  • Supports OpenAI-compatible, China-based, and local Ollama / LM Studio providers without locking the project into one model vendor.
  • Added CLI and MCP Server prototypes for Claude Code, Codex, MCP Agent, and context-pack workflows.
Technical valuePre-send safety checks, redaction, and routing reduce sensitive-content exposure and make model selection more controllable.
Engineering abstractionScanner / Redactor / Router / Provider Registry are separated for future rules and provider extensions.
ScopeCurrent version focuses on local preflight, redaction, routing display, and provider configuration. Model calls require user-configured Provider keys.
